2026-07-22



问题现象

ESP32-S3通过MQTT连接华为云，当云端向设备下发消息时，系统触发 `Guru Meditation Error (StoreProhibited)` 异常，随后WiFi断开重连，无法正常处理云端指令。



原因

MsgData\_t 结构体中的data指针未初始化：在mqtt\_event\_cb回调中，直接使用未分配内存的指针进行memcpy操作，导致写入非法地址，触发内存保护异常。



解决方案

修改 MsgData\_t 定义：将uint8\_t \*data改为固定长度数组uint8\_t data\[256]，避免野指针问题。

&#x20;  // task\_handle.h

&#x20;  typedef struct {

&#x20;      uint8\_t data\[256];

&#x20;      uint16\_t length;

&#x20;  } MsgData\_t;



验证结果

修改后重新烧录，云端下发JSON指令（如 `{"content":"hello?"}`）可正常接收并打印，系统运行稳定，不再触发崩溃或WiFi重连

2026.8.10

问题概述
ESP32主控连接两台STM32：执行器板通信看似正常；**传感器STM32，ESP32收不到其返回数据**。
现象：
1. ESP32可正常下发命令给传感器STM32，STM32接收解析正常；
2. STM32发送接口返回`HAL_OK`，确认数据已经从TX引脚发出；
3. ESP32无传感器接收日志，收不到应答帧、按键上报帧；
4. 执行器通信只是偶然可用，存在潜在丢包风险。

排查过程
1. STM32侧增加发送状态打印，确认发送成功，排除STM32驱动、协议、传感器采集故障。
2. 交叉接线测试，排除接线、电平、共地等硬件问题，定位ESP32软件驱动问题。
3. 代码分析：`esp_intr_alloc()`第一个参数为**中断源编号**，不能直接传入UART实例编号`UART_NUM_x`。

根本原因
UART自定义中断注册参数错误**
原代码将UART实例号`UART_NUM_1`直接传给`esp_intr_alloc`，注册到了WiFi相关中断源，**并未绑定真正UART硬件中断**。
UART接收到的数据存留在ESP‑IDF驱动内部缓冲区，不会拷贝到用户自定义环形缓冲区，上层任务读取始终为空。
> 执行器UART存在完全相同BUG，依靠WiFi中断偶然触发实现通信，属于不稳定巧合，会随机丢帧。

## 修复方案
利用`uart_driver_install()`自带官方中断与缓冲区，**移除自定义中断、信号量、用户环形缓冲区**。
1. 修改`uart_sensor.c`：接口对外保持不变，内部直接调用IDF原生API：
    - 接收：`uart_read_bytes()`
    - 获取缓冲长度：`uart_get_buffered_data_len()`
    - 清空接收：`uart_flush_input()`
2. 同步改造`uart_actuator.c`，消除执行器潜在丢包隐患。
> 上层业务文件`task_sensor.c`、`task_actuator.c`无需修改。

## 修复验证
1. ESP32正常接收传感器应答帧、按键上报帧，接收日志正常输出；
2. 温湿度、距离解析正常，MQTT上报功能正常；
3. 执行器通信稳定性提升，消除随机丢包隐患。

## 经验总结
1. ESP‑IDF：`esp_intr_alloc`入参是**中断源ID**，不等于外设实例编号；
2. 优先使用驱动自带缓冲接口，避免重复自建中断+环形缓冲，容易引入绑定错误；
3. “偶尔正常”不能代表代码正确，需要对照API手册校验底层逻辑；
4. 串口调试分层排查：硬件层→底层驱动层→协议解析层。
